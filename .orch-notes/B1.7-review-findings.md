## Blocker B-1 — P2/T2's "orphaned clause" is not orphaned, and T2 as written breaks every dispatch

**Report claim.** P2: the clause "the full suite is the gate's row, never a
unit's" is "restated verbatim in five files and owned in none... genuinely
orphaned, not just duplicated." T2 prescribes: give it one owner in
`rules/verification.md` and "make every pack craft.md link to it," called
"a two-line prose fix in six files... a change with zero downside," ranked
#4 in the change list.

**What the tree says.** The clause has two mechanical owners, neither
mentioned in the report:

1. `tools/validate_support/duplication.py:44-66` registers a declared
   duplication family named `"verification-scope anchor"` whose `reason`
   field states the case verbatim: *"Every pack carries this sentence by
   that mandate, not by drift -- each names its own check vocabulary, and
   the closing clause states the shared law itself, which has exactly one
   wording."* The canonical clause list is at `:58-65`, ending in the exact
   string at `:64`. The five restatements are a reasoned, registered
   exemption, not neglect.
2. `scripts/tickets_assignment.py:50-54` declares
   `CRAFT_SCOPE_ANCHOR = "gate's row"` with the comment *"The craft owns
   its verification scope; this finds the sentence rather than restating
   it."* `_craft_scope()` at `:140-165` scans the craft's `## Stages` /
   `## Lens` bullets for that literal anchor and quotes the matching
   sentence into the child's launch prompt.

**Why it is a blocker.** `_craft_scope()`'s own docstring at `:144-145`:
*"A craft that declares no scope gets no quote, and the prompt's standing
line answers alone."* Replace each craft.md's sentence with a link, as T2
prescribes, and the anchor matches nothing: every dispatch silently loses
its pack-specific verification-scope line and falls back to the generic
standing line at `scripts/tickets_dispatch_launch.py:316`. A reader
executing the "zero downside" change degrades live dispatch behavior
across all five packs.

**Live proof.** This ticket's own launch prompt carries the line *"That
craft sets your verification scope: 'Run the narrow affected document
checks; the full suite is the gate's row, never a unit's.'"* — the
content-pack sentence, quoted by that anchor, on this very dispatch.

**Aggravating.** The report cites `tools/validate_support/duplication.py`
in T6 (for `CELL_SIMILARITY_THRESHOLD`), so the file was in hand; the
allowlist entry naming this exact clause, ~20 lines away, was missed.

**Repair direction (prescription, not applied).** Keep the five
restatements. If P2's real complaint is that `rules/verification.md`
carries no statement of the law, the safe change is additive: state the law
in `rules/verification.md` *and leave every craft.md sentence intact*,
because the craft sentences are machine-read anchors, not prose
duplication. Any change to them must keep `CRAFT_SCOPE_ANCHOR` matching.

## Blocker B-2 — the 925-word ceiling is enforced; the table says it is not, and its verdict would break the enforcement

**Report claim.** Limits table, row *ARCHITECTURE.md's own ceiling*: "925
words | `ARCHITECTURE.md:3-5` (stated) — **enforced nowhere** (B1.3: grep
for '925' across all of `tools/*.py` returns zero hits) | **Move to config
and enforce it**." Ranked-list item 6 repeats it as one of "two live
defects (the 925-word and routing-block ceilings' complete
non-enforcement)."

**What the tree says.** `tests/test_architecture_owners.py:27-29`:

```
# The map states its own ceiling; nothing else in the tree states it, so the
# number a reader is held to is the number the file carries.
CEILING_RE = re.compile(r"Ceiling: (\d+) whitespace-delimited words")
```

`ARCHITECTURE.md:3` carries `Ceiling: 925 whitespace-delimited words`. The
ceiling is enforced — by a test that reads the number out of the prose
instead of hardcoding it.

**The report contradicts itself.** P9 describes this same construct
correctly and praises it: "`tests/test_architecture_owners.py:27-29`'s
`CEILING_RE` reads ARCHITECTURE.md's word ceiling at test time instead of
hardcoding it — the right pattern." One document, two incompatible claims
about one fact; the table's verdict rests on the wrong one.

**Why it is a blocker.** "Move to config" deletes the number from
`ARCHITECTURE.md:3`, at which point `CEILING_RE` matches nothing and the
enforcement the report elsewhere calls exemplary is silently removed — the
opposite of the row's stated intent ("Move to config **and enforce it**").

**Root cause is a seam, not carelessness.** The non-enforcement claim rests
on a grep scoped to `tools/*.py`, inherited from B1.3, whose surface was
tools/installer/reader/CI. The enforcement lives in `tests/` — B1.5's
surface. Neither lane owned the cross-surface question "is this number
enforced anywhere," so a surface-scoped negative became a whole-tree
negative. See §Seams.

**Checked and clean, by contrast:** the same row's neighbour — the project
routing block's 400-word ceiling, also called unenforced on B1.3's grep —
survives my check: no `.py` file in the tree contains "routing block" or
"routing-block". That verdict stands.
