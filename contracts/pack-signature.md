# Pack signature

The cells every pack provides, and the constraints between them. A generic
workflow consumes pack data through these flat leaves; a pack provides no
control flow and no skill binding. The pack's identity is a SHA-256 digest of
the resolved cells, local reference bytes, signature bytes, and resolver
normalization version.

## Execute cells

These leaves feed artifact-producing execution:

| cell | binding |
| --- | --- |
| slicing | how a spec cuts into work items and the item extensions the domain adds |
| workspace | identities, isolation, candidate diffs, and conflict handling in this domain; the adapter key is declared separately |
| required_spec_fields | fields a spec must carry for decomposition to accept it |
| craft | reference owning the domain's vocabulary and shape |
| adapter | one stable registered workspace mechanism key |
| stages | ordered stage names available to the pack's execution sequence |
| assembly | one stage name for a terminal assembly item, or `none` when no terminal item exists |

## Check cells

These leaves feed read-only checking:

| cell | binding |
| --- | --- |
| lens | the domain's review criteria, normally the pack craft's `## Lens` section |
| evidence | artifact-appropriate evidence methods and identities a checker may challenge |
| craft | the same vocabulary and shape reference consumed by execution |

## Outline cells

These leaves feed intake, where a root is frozen before any of it is cut:

| cell | binding |
| --- | --- |
| outline | the domain's taste for a frozen root: what a well-formed one carries, which intake questions are worth asking, and its exemplar policy |
| required_spec_fields | the fields decomposition will demand, read at intake as the checklist a root must satisfy before seal |
| craft | that same reference again, so intake names terms the way execution and checking will |

The typed leaves are `adapter`, `stages`, and `assembly`; downstream machinery
branches on each. The other leaves are prose or references and remain
individually named rather than nested beneath a conceptual parent. A named
stage is data, not a host skill binding. Every lane is a flat projection over
the same leaves: `craft` sits in all three and `required_spec_fields` in two,
and neither is copied to earn its second slot.

Sharing constraints, checked at pack review:

- The terminal assembly item's Goal names the final integrated result.
- Every candidate form emitted by slicing is expressible in workspace.
- Every domain term another cell uses is defined once in craft, or inline in
  the cell that uses it.

Purity: a pack body contains no delegation language, stop states, conditionals,
or Return contract. The validator states its mechanical checks; the authoring
standard owns the remaining judgment.

Admission: a domain earns a pack for materially different artifact evidence or
workspace semantics. A cell earns its slot only when its content differs
between packs and no other cell already owns that content.
