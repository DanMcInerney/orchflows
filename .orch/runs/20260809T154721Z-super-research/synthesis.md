## 3. Provider-neutral evidence and wrong-merge contract

`AcquisitionManifest v2` is the sole acquisition request. It contains IDs for manifest/phase/slice/request; discover query or caller-frozen direct seed; hydrate prior-artifact and selected candidate IDs; source role, platform family, content kinds and requested payloads; closed-open interval, `published|updated` basis, and frozen UTC `as_of`; requested native view; ordered route grants; and hard call/page/item/byte/duration/comment/reply-depth/transcript-segment/context caps. It contains no token, cookie, secret value, profile path, arbitrary endpoint, module, executable or command. [P07:R0,P0,F0]

Each adapter call returns exactly one `NativePage` with `records`, `cursor_out`, native-order name and monotonic-time declaration, start/end timing, warnings, native outcome, and explicit field/content/coverage loss. The adapter performs no second call. The core alone converts pages into one immutable `AcquisitionArtifact v2`. Every attempt and record has:

| Field family | Required fields |
| --- | --- |
| Identity | artifact, manifest, phase, slice, request, attempt, candidate and record IDs; adapter and schema versions |
| Platform relation | platform/instance, `native_identity_namespace`, canonical content kind, native item/thread/root/parent IDs, aliases/relations, canonical locator, author, community/container; missing native identity is explicit loss |
| Content | title/body/media locator, media type/language, exact content hash, truncation/completeness; transcript media/track/provider/kind and segment offsets; caption routes also preserve requested format/language, translation request and `machine_translated` state |
| Time | requested/applied interval and basis; raw/parsed published, edited/updated, observed and engagement-observed times; confidence `authoritative\|reported\|derived\|unknown`, source and precision |
| Engagement | append-only snapshots of platform namespace, exact native metric name/value and observation time |
| Page/order | requested view, native view/rank/position, page index, cursor in/out, list index, native-order time-monotonicity proof, stop reason |
| Access/provenance | access class, route ID/provider, source upstream identity, requested/final target and redirects, discovery query/hit lineage, policy/config version; configuration-presence boolean may appear at run level, but no credential/session slot or identifier enters an artifact |
| Outcome/loss | `ok\|empty\|partial\|failed\|refused`; typed reason; warnings; explicit field/content/coverage loss; fallback-from and loss basis |
| Audit | requested and consumed calls/pages/items/bytes/duration per role/slice; provider usage remains opaque data |

Kinds are `web_hit`, `web_page`, `feed_item`, `news_item`, `post`, `thread`, `comment`, `reply`, `media`, `transcript`, `transcript_segment`, `repository`, `commit`, `issue`, `pull_request`, `discussion`, `release`, `paper`, `job`, `market`, and `generated_text`. Provider prose, ASR, summaries and clusters are `generated_text` or generated transcripts with lineage; they are acquired artifacts, never findings. [P01:L3-L4] [P03:S05,S09,S14] [P07:R0]

For the first-release YouTube video-plus-transcript scenario, `youtube_data_api` creates the `media` record under `native_identity_namespace=youtube:video` and `native_item_id=<video_id>` and keeps metadata, engagement, comment threads and replies as separate linked observations. `youtube_captions_oauth` lists a caption track for that same `video_id` and emits a distinct `transcript` plus any `transcript_segment` records related by `media_id=<video_id>` and `track_id=<caption_track_id>`; neither record merges with video description, comment text, another track or a publisher transcript. Wrong-merge rules are deterministic and request-local to one manifest/prior-artifact chain; no identity group or dedupe cache silently carries across runs:

1. Strong identity is `(native_identity_namespace, native_item_id, canonical_content_kind)`. The namespace is part of the key: for example GitHub host/repository/object family, feed publisher/canonical-feed identity, Mastodon instance origin, or platform service. It groups observations but never overwrites bodies, dates, routes, or engagement snapshots.
2. Without strong identity, exact-content grouping requires `(normalized_final_locator, content_kind, exact_content_hash)`.
3. A comment/reply never merges with its thread, parent or sibling. A GitHub issue-endpoint row with a PR marker normalizes once as canonical kind `pull_request` with relation `issue_surface`; conditional PR hydration enriches that record and never creates a second `issue` object.
4. Changed content at one URL remains a distinct observation/version.
5. Mastodon local IDs include instance origin; RSS GUIDs and Atom IDs include publisher/feed identity; a missing RSS GUID uses a declared publisher-scoped fallback key and `identity_weak=true`; Reddit fullnames retain `t1_`/`t3_`; GitHub identity includes host/repository/object kind; Bluesky uses AT-URI plus CID; YouTube comments retain video/thread/parent, while caption tracks retain video/track identity and relation rather than merging into the video. [P02:S1,S8-S12] [P03:S01-S04,S07-S14]
6. Cross-platform matches are duplicate-group links, never identity merges. Search result, hydrated target, provider summary and native platform item remain linked distinct records.
7. Several wrappers over one page/API are one upstream for independence. `gh` and GitHub REST/GraphQL, a Digg cluster and attached X posts, multiple search providers returning one page, or a provider synthesis and its citations do not counterfeit convergence. [P01:L1-L4] [P06:S14]
8. Raw caps count all received records. Exact duplicates do not displace unique groups under the context cap.

The pure `project.context` operation accepts only caller-selected record IDs and named transcript windows. It emits one payload per exact group, every provenance edge, selected comment ancestor chains, and requested transcript neighbor segments. It performs no I/O and makes no evidence selection or judgment. [P07:P0,C0]

## 4. Executable timeliness, views, caps and concurrency

For every slice the manifest freezes `[start,end)` in UTC and one basis, `published` or `updated`. Adapters record the provider filter actually applied and its semantics. Hydration may add a better native/page time but never overwrites the index observation. [P02:S4,S8,S10-S14] [P03:S01-S14] [P05:S1-S14]

The deterministic algorithm is:

1. Resolve `basis_time` only from the caller-selected field. `edited_at` never substitutes for publication unless basis is `updated`.
2. Preserve raw value, parsed value, source, precision and confidence. A search-provider date is `reported|derived` under provider identity, never a native authoritative time.
3. A hard-window record is `ok` only when its route supplies a usable requested-basis time and `start <= basis_time < end`. An A5 hit may be `ok` as a timely **index observation** under provider identity, but a provider-reported/derived date can never promote it to timely hydrated page or native-platform evidence; that record remains a discovery lead/partial until the target route supplies its own admissible time. Stale records are excluded with reason; unknown/derived-only target times remain a separate partial/unknown bucket and cannot silently satisfy the interval.
4. Early stop is legal only when the adapter descriptor and active view prove non-increasing authoritative/request-basis time and every decision-relevant item on the page has known time. After the first wholly older page, stop before another call. Any unknown time, in-window item behind a boundary, or order violation disables the descriptor.
5. `top`, `best`, `hot`, `most_commented`, and `most_replied` are not presumed time-monotone. Use a native server interval where documented; otherwise bounded local filtering emits `recall_window_partial`.
6. Feed snapshots, Reddit mutable listings, Bluesky incomplete cursors, HN capped arrays, GitHub update-based `since`, Atom `updated`, TikTok lag, and changing market/engagement values retain their platform-specific limitations. [P02:S1,S7-S14] [P03:S07-S14] [P04:S3-S4]

Views are deterministic and attention-only. The manifest freezes one UTC `as_of`; replay never reads the wall clock. An adapter descriptor declares, for each platform/content scope, the exact native metric name eligible for `comment_count` and/or `reply_count`. Metric names are not inferred, aliased between platforms, summed across routes, or compared cross-platform; absent, nonnumeric or differently named values are missing rather than zero.

- `newest`: within one platform/content family, usable requested-basis time descending, then normalized native-ID-present flag, normalized native ID and record ID; missing IDs sort after present IDs and record ID makes the key total.
- `cross_source_chronology`: across every source role, usable requested-basis time descending, then platform/namespace, canonical kind and record ID; unknown dates are emitted in a separate stable bucket. This organizes dates across sources without comparing attention.
- `native_top`: only the platform's declared native order/rank, then normalized native-ID-present flag, normalized native ID and record ID. Provider search rank is a discovery view, not platform authority.
- `most_commented`: one platform namespace, content scope and adapter-declared native comment-count metric, using the total engagement comparator below.
- `most_replied`: one platform namespace, content scope and adapter-declared native reply-count metric, using the same total engagement comparator.

For either engagement view, first choose per record the eligible snapshot with the greatest `engagement_observed_at` such that `engagement_observed_at <= as_of`; ignore future snapshots and treat no eligible snapshot as missing. Then sort by this exact total key: known-metric bucket before missing; native metric value descending when known; requested-basis-time known bucket before unknown; requested-basis time descending when known; normalized platform item ID ascending; and record ID ascending as the terminal tie. In tuple terms this is `(metric_missing, -metric_value_if_known, basis_time_missing, -basis_time_if_known, normalized_platform_item_id, record_id)`, where a missing platform item ID normalizes to one declared terminal sentinel that sorts after every valid normalized ID. Stale but eligible values remain values at their recorded snapshot time, never projected forward. Replay fixtures must cover stale-only, changing multiple snapshots, a future snapshot after `as_of`, missing/nonnumeric metrics, missing basis time, missing native ID and exact-value ties, and must prove identical bytes/order across wall-clock changes.

No view compares Reddit score, HN score, YouTube views, GitHub reactions, Polymarket prices, TrustScore, Stocktwits likes, feed placement or provider relevance across platforms. None contributes to claim confidence, authority or independence. Engagement observations are append-only snapshots. [P01:L1-L4] [P03:S02,S07-S10] [P04:S3-S5]

Every source-role slice must provide concrete `max_calls`, `max_pages`, `max_items`, `max_bytes`, and `deadline`; page hydration adds selected-page and per-page bytes; community adds root/comment/reply-depth; media adds selected-media/transcript-segment/bytes; code adds repository/object/comment/nested-cursor; feed adds feed-item/transcript-link caps. All fallback routes for one platform debit the same frozen slice/platform allowance, so REST/API/CLI/index alternatives cannot multiply capacity. Values are frozen per request/scenario, not copied from anchor depth profiles and not claimed universal before benchmarks. Each role has reserved capacity; one source cannot consume another role's cap and unused capacity is not silently reallocated. [P01:L2-L4] [P07:R0,P0]

One global `max_in_flight`, one hard per-adapter limit and one per-upstream/principal governor own concurrency. Independent source slices and selected hydration items may run concurrently. Pages in one cursor chain, pages of one comment tree and nested discussion cursors are serial. Output order is manifest slice, selected candidate, page and native position, independent of completion time. A call/page/item/byte/deadline/rate/comment/reply/transcript stop occurs before another call and preserves completed records as partial evidence with exact terminal reason. [P03:S03,S09] [P06:S8-S11] [P07:P0,C0]

## 5. Acquisition flow, efficiency claims and falsifiers

The only call graph is:

```text
ordinary research freezes question, roles, interval, grants and caps
  -> discover manifest
  -> validate -> authorize -> bounded scheduler
  -> literal adapter branch -> one bounded read -> parse NativePage
  -> core cursor/date/cap loop -> normalize/views -> discovery artifact
ordinary lane selects candidate IDs and required payloads
  -> hydrate manifest(prior artifact, selected IDs, payloads)
  -> serial pages per item; bounded independent items concurrent
  -> normalize/group/views -> evidence artifact
ordinary lane selects record IDs
  -> pure context projection (zero calls)
  -> lane findings -> ordinary orchflows synthesis
```

Hydration payloads are explicit: `page`, `metadata`, `thread`, `comments`, `replies`, `engagement`, `captions`, `publisher_transcript`, `release_assets`, `pr_detail`, `discussion_comments`, or `discussion_replies`. Selection never authorizes a new route. A discovery response may short-circuit hydration only when it already contains every requested payload with full identity, time, route and loss lineage. [P01:L2-L6] [P03:S01-S14] [P07:P0]

| Efficiency decision | Calls/content/model work avoided | Falsifier / required response |
| --- | --- | --- |
| Discover, lane-select, hydrate | Hydration calls, bytes and model input for rejected candidates | Same candidates/payloads: hydrate-all uses equal/fewer calls/bytes with no worse required yield; widen discovery or remove split for that route. [P05:S1-S14] [P07:P0] |
| Payload-specific hydration | Unrequested comments, replies, page bodies, metrics or transcripts | A required record is lost or work equals full hydration; required payload may not be dropped for economy. [P03:S01-S14] |
| Complete-at-discovery short circuit | One second call | Any requested identity/date/comment/metric/loss missing while marked complete disables it. [P07:P0] |
| Monotonic date stop | Every page after first wholly older page | In-window/needed unknown item behind boundary or native-order violation disables stop and is a wrong-result fixture. [P02:S1,S4,S8,S12-S14] |
| Per-role/payload caps | Long-tail pages, deep replies and transcript bytes | Decisive required evidence exists only beyond cap; caller must explicitly widen and preserve old partial artifact. [P01:L2-L6] |
| Bounded concurrency | Wall-clock only; no call/byte claim | Fake-clock replay shows no gain, rate amplification, cap overshoot or unstable bytes/order; lower/disable setting. [P07:P0] |
| Conservative candidate dedupe before hydration | Calls only for candidates with the same strong native namespace/ID/kind or a prior record already complete for the payload. URL/content-hash grouping occurs after hydration and avoids context bytes, not speculative calls. | Any distinct platform item suppressed, a cross-provider URL treated as identity, changed content collapsed, lost provenance or unique-record displacement; strengthen key and restore hydration. [P03:S07-S14] |
| Selected context with ancestors/windows | Full-thread/full-transcript model bytes | Claim cannot be judged from selected records plus ancestors/windows, or output is not smaller; widen projection only. [P07:P0] |
| Core-owned cursor loop | Hidden overfetch and calls after terminal bounds | Any adapter-owned second request or ledger call after a stop fails admission. [P07:C0] |
| No cache/async/model/provider writer | Cache lifecycle, polling, model calls and duplicate judgment | Required synchronous workload fails, or frozen repeat proves benefit without custody/evidence regression; reopen only that feature. [P07:P0,F0] |

The benchmark has seven frozen workloads: recent web/news page; public HN Reddit-like thread; registered Reddit OAuth post/comment tree; official X posts/reference edges; YouTube Data API video/comments joined to one authorized official caption track; GitHub repository/issues/discussion/release activity; and RSS/Atom with selected page/transcript hydration. The engagement workloads replay stale, changing, future-after-`as_of` and missing metric snapshots through the total comparator. Compare identical source roles, selections, payloads and caps against hydrate-all, sequential, no-date-stop and full-context baselines. Record scenario pass, typed-loss correctness, calls/pages/bytes, fake-clock duration, projected bytes, false merges, provenance, deterministic bytes, and secret/write violations. Provider quality, optimal universal caps and price superiority remain unproved until an equal-budget authorized workload exists. [P02:S1-S7] [P03:S01-S14] [P05:S1-S14] [P07:R0,P0]

## 7. Authority, custody, failure and threat model

Each manifest freezes ordered route grants:

