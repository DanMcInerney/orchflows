# Direct source inspection

Resolve `research-acquire --resource skills/research-acquire/scripts/inspect_source.py` through the installed orchflows CLI. Invoke that script with the supplied Python runtime:

```text
python <resolved-script> youtube-transcript --url https://www.youtube.com/watch?v=WZgpn0BzVo4 --output <outside-package>/caption.json --window-start 2026-08-12T14:56:12Z --window-end 2026-09-11T14:56:12Z
```

The command reads one known video. It creates no plan, search queries, agents, reviews or synthesis. Captions are video speech; they are not viewer comments or verified speaker attribution. Use native source access for discovery and audience comments.

`--language en` is the default; pass the actual track language when known (for example, `--language th`). Only one language is requested. `--timeout-seconds` defaults to 45 and accepts 1–120; `--max-chars` defaults to 24,000 and accepts 1–100,000. Output text is a prefix when truncated; the adjacent VTT or JSON3 support file retains captions and timing for inspection, with its SHA-256 in the receipt. Retained support is capped at 8 MiB. This output cap is not a network-byte quota: yt-dlp may download a larger temporary subtitle before the reader rejects it.

`caption_track` retains normalized language, kind, cue count and duration when known. Its `automatic` value is true, false or null for unknown. InnerTube supplies track kind; yt-dlp classification requires the selected subtitle URL to match exactly one of its manual or automatic caption collections. Automatic generation can include translated manual captions, so this classification does not establish ASR. Missing or ambiguous metadata stays unknown, without another network read.

The fixed acquisition path is one yt-dlp attempt (at most 30 seconds or 70% of the allotted time), then at most two existing InnerTube adapter calls: player caption discovery and its timed-text continuation. The fallback runs in a child with only the remaining wall time. There are no reader retries. yt-dlp internal HTTP requests are not counted individually; all extractor, fragment, file and HTTP retry settings are zero. Process startup, parsing and file writes can add small overhead to the acquisition deadline. No playlist is followed, even if the supplied watch URL contains a playlist parameter.

yt-dlp is optional and must already be installed. The reader prefers a module importable by its Python runtime, otherwise an executable on PATH. It installs nothing. Its Android player client follows the successful last30days route; cookies, browser-cookie loading, user configuration and plugin directories are explicitly disabled. No SSH route, paid provider, key lookup or login is added. Missing yt-dlp remains visible as `dependency_missing` in the attempts list before public fallback; live availability of either backend can change.

Exit 0 means usable caption text was retained, including a completed subtitle left behind by a later extractor failure or timeout. Those process failures remain in the attempt receipt. Exit 3 means no usable caption was acquired; JSON still records the attempts. Exit 2 is a usage error. Captions absent in one requested language, access refusal, empty HTTP 200, missing dependencies and timeouts remain different statuses. Success does not mean the item matches the requested window.

Exact window instants use `[start, end)` with a UTC offset or `Z`. Alternatively, `--start-date` and `--end-date` specify inclusive UTC calendar dates. `publication` preserves metadata precision and provenance. `date_relation` is `inside`, `outside`, `boundary_uncertain`, `unknown` or `not_requested`; day-only metadata overlapping an exact cutoff cannot count as inside. Native date-only fields without a timezone use an interval widened to cover UTC-12 through UTC+14. An undated caption never gains a publication date from collection time. Video upload/publication dates do not date viewer comments or independently date the caption track.
