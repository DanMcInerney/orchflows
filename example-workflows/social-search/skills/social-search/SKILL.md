Stay in the current orchestrator. Resolve core dependencies and one outer run through [home and runtime](../../references/home-runtime.md), unless the caller already supplied that context. Load the resolved orchflows-light:delegate-work skill for fresh native children and the resolved native host guidance for capabilities, workspace access and inherited model defaults. Source workers and the judge perform their own assignments without spawning. If native delegation is unavailable, report that this workflow could not run; the [site search](../search-site/SKILL.md) and [ranking](../rank-research/SKILL.md) skills remain independently usable.

## Select and allocate

Resolve the question, intended use, publication/event window or explicit all-time, separate information cutoff or forecast horizon, named sources/routes, required details and output from the ordinary request. Resolve material recency ambiguity before reads; there is no implicit thirty-day window. Preserve requested rigor, verification, audience, length and citation requirements. Default to a concise ranked cited report with synthesis; honor evidence-only, offline HTML and caller-supplied checks.

Read the [source registry](references/source-workflows.md), choose relevant sites and load only the selected instructions as needed. Named sources remain required unless the caller says otherwise. Use generic named-domain assignments when useful. Do not automatically launch every profile or widen a single-site request into a fanout. A small routing/discovery read is permitted when necessary to choose sites; count it against the total.

Set a shared retrieval/result budget and finite deadline before launch. Allocate nonoverlapping per-site allowances, including depth, and reserve room for one possible targeted evidence follow-up and the judge. A short assignment table suffices. Public read-only native tools are the default; [research-acquire](../research-acquire/SKILL.md) is optional when its bundled reads, deterministic caps, receipts or resume are needed or requested. Pass hard limits only to methods that can enforce them, or return the incompatibility before reads. Native tool calls are not measured network attempts; retain unknown usage, backend per-plan limits and actual deadline constraints honestly. See [provenance and checks](../../references/provenance.md) for the backend's guarantees.

## Run selected source workers

Use delegate-work with the resolved Research standard, one fresh worker per independent selected site by default. Give each worker its selected skill, resolved scope and required depth, permitted source/access routes, allocated bounds/deadline and unique writable output directory from the run context outside the package. Pass the concrete resolved package/core/runtime paths and parent run context so workers do not repeat setup or create child runs. For repository assignments, use the worktree boundary in native host guidance; ordinary research artifacts need only their own task directories. Each worker uses [prepare-evidence](../prepare-evidence/SKILL.md) in its own context before and after collection, returning `results.md` under that skill's [evidence contract](../prepare-evidence/references/evidence-contract.md), with available raw support and receipts. Preparation is part of the worker's work, not another agent or acquisition stage.

Launch independent assignments concurrently up to the actual available native child capacity and source limits. With fewer slots, use bounded waves, joining completed work before launching the next wave; do not silently promise simultaneous work that the host cannot run. Serialize separate backend plans sharing an origin and any native reads subject to shared origin/provider pacing or hard limits. A shared native search tool still allows independent-site overlap when no shared limit requires serialization. No nested worker delegation or shared writable results. Retain native worker handles for the possible targeted continuation.

Join each selected worker's actual result. Record a missing, failed or interrupted assignment explicitly; silence is not no results. If a failed or timed-out worker still runs, stop or settle its reads before reallocating any allowance. Reclaim only known unused budget, preserving uncertain reservations; no speculative duplicate workers or automatic retries. Keep refusals, named-source restrictions, meaningful date/window gaps and required details visible.

## One fresh judge

After the selected workers finish or return explicit gaps, use delegate-work once to launch a fresh [rank-research](../rank-research/SKILL.md) judge with the resolved Research and Writing standards when appropriate, the resolved request, requested output location and every actual source result/supporting artifact. Include the same resolved paths/run context, missing-worker and budget/coverage limitations, plus worker preparation notes. The judge consumes compatible handoffs without repeating preparation; it performs its own substantive evidence assessment. The judge inspects support, deduplicates and reranks evidence globally, then writes the requested report; source workers do not draft competing final answers.

Allow at most one targeted evidence follow-up round. Continue only the relevant original source workers with the judge's concrete gaps and the remaining reserved authority/budget, then continue the same judge with their updated results. Apply the same capacity and shared-origin limits. If continuation is unavailable, preserve that gap. Refusals and exhausted bounds stop affected reads; do not restart the pipeline or introduce another repair loop.

Return the judge's report or requested artifact, its completion status, dates, source support and material limitations. Required gaps block full completion; unsupported central conclusions yield evidence and blockers. Preserve backend packet paths/digests and checks actually run. A separate independent review of the judge's final prose is optional only when requested; then resolve and compose orchflows-light:delegate-review over the actual artifact and evidence within the agreed bounds. Do not describe the default report as independently reviewed prose.

If this invocation owns the outer run, write the actual outcome summary and finalize it through the shared home/runtime convention. Nested use returns its report and limitations to the owning caller for finalization.
