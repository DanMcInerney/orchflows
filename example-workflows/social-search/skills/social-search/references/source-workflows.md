# Select source workflows

Choose sites for the question and explicit source requirements, not for the number of installed profiles. Load only selected skills. These are independently reusable examples; each wrapper runs [search-site](../../search-site/SKILL.md) in its current worker context.

| Source skill | Useful evidence |
| --- | --- |
| [search-reddit](../../search-reddit/SKILL.md) | Community experience and discussion in relevant named or discovered communities. |
| [search-youtube](../../search-youtube/SKILL.md) | Video claims, demonstrations and commentary supported by inspected content or transcripts. |
| [search-x](../../search-x/SKILL.md) | Public account statements and conversations with direct post attribution. |
| [search-hacker-news](../../search-hacker-news/SKILL.md) | Technical discussion and linked reporting, preserving comment context. |
| [search-github](../../search-github/SKILL.md) | Repository activity, releases, issues and technical implementation evidence. |
| [search-polymarket](../../search-polymarket/SKILL.md) | Market questions, outcome prices and resolution terms for the requested horizon. |
| [search-site](../../search-site/SKILL.md) | Any other named site/domain, including primary sources without a wrapper. |

Source identity is distinct from an authorized access provider. For example, an archive response about a Reddit post is Reddit-origin evidence obtained through that archive, not a fresh Reddit observation. Profiles guide source fidelity; they do not grant credentials, alternate routes or extra budget. Multiple sites repeating one underlying claim are not independent corroboration.

Give each selected skill the ordinary resolved task, limits and a unique result directory. Combine their actual evidence in a fresh [rank-research](../../rank-research/SKILL.md) context. A standalone request can instead read a single skill directly; it needs neither this coordinator nor a cross-site judge unless the user wants that synthesis.
