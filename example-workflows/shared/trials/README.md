# Behavioral trials

Run each request from an unrelated workspace with core and the required libraries copied to an isolated home. Resolve paths through its CLI or supported native registration. Give the coordinator only the request, input fixtures and declared dependencies, without the authoring conversation or the expected-behavior document. Run outputs stay outside this package.

| Scenario | Purpose | Status |
| --- | --- | --- |
| [Design comparison](design-comparison/request.md) | Existing `design-loop:test-increment` composes shared comparison without an extra reviewer or adoption | Executed 2026-09-17: one reviewer exercised both versions on all four cases; identified the intended improvement and empty-input regression; no repair or adoption |
| [Office decision](office/request.md) | A personal library uses both shared processes, private guidance and one shared allowance | Executed 2026-09-17: comparison, review and one fresh repair used three starts; corrected costs and unsupported claims; subsequent zero-allocation call made no edit or launch and reported missing review |

The expected-behavior documents are for the evaluator after execution. Record exact package revisions, native child identities, allocation and consumed calls, candidate identities, actual outputs, preparation and gaps. Filesystem copies do not establish invocation by native skill name or portability to another host. No expected answer should be included in a worker's initial prompt.

These observations used core 0.8.0, shared 0.1.0, design-loop 0.1.1 and the bundled personal 0.1.0 fixture. Coordinators started with fresh contexts, resolved copied packages through the isolated home's CLI and applied their file instructions; the primitives launched actual native children. Original inputs and tested instruction files remained unchanged. The revised office memo has repair verification, not a new independent acceptance. Local evidence is retained outside the packages under the authoring checkout's `reports/shared-process-trials/`.

Implementation review then found a premature return on the no-repair branch. After correction, a separate invocation used one fresh reviewer on the delivered office memo, received no actionable findings, made no repair and still executed caller-required Python checks of costs, difference and length. All checks passed with unchanged inputs. This affected-branch check used the author as coordinator, not a fresh coordinator, and is recorded separately from the earlier trials.

Not exercised: native skill-name registration or invocation, other hosts, explicit model/effort overrides, broader reviewer allocations, blinding, interruption/resumption, or benchmaker's full authoring process. The design-loop trial covers its comparison leaf, not a full cycle. These runs establish neither comparative speed nor general reliability.
