# Evolve

Improvement claims follow observed outputs under a stable task-specific evaluation. Keep the caller's purpose and required behavior visible when assessing tradeoffs. Separate measurements, judge preferences and untested possibilities. Failed attempts should leave a concrete lesson rather than an invented score.

## Make

Start with available task skills and a simple revision policy. Prefer one clear hypothesis about the incumbent. Periodically revisit a promising different approach or combine complementary ideas; wider tournaments should test distinct hypotheses, not duplicate rewrites. Do not repeat a failed idea without new evidence.

Use compact failure records: what was tried, what happened and what it suggests trying next. Read relevant evidence rather than carrying the whole transcript into each prompt. Keep a small archive of meaningfully different approaches alongside the original, current best and previous best.

For a harness proposal, trace a recorded failure to one minimal change in prompts, tools, memory selection, verification practice or search policy. Prefer a change whose effect can be distinguished in actual output. Better-looking instructions alone establish no behavioral gain.

Plan the available work around both production and confirmation. Reserve enough budget for comparison, required judges, meaningful confirmation and state persistence before choosing tournament width or repetitions. A narrower experiment is often more useful than several candidates with no affordable confirmation. Run independent candidates concurrently where resources permit; serialize measurements when contention would distort them. Cheap screening can preserve confirmation budget for promising candidates.

These methods support search; the selected workflow owns bounds, independence, evaluation versions, promotion and continuation. Changing technique cannot relax those obligations.
