Our calendar-operations agent books meetings for the team by editing our calendar files. It runs on Claude Haiku 4.5 at low effort with the tools Read, Write, Edit, Bash, Glob and Grep, and the agent directory is `./subject/agent/`. Every booking request comes with the team's booking policy, `policy.md` in the workspace. The agent has to follow it and must not damage anything already in the calendars.

We wrote the `booking-rules` skill, in `./subject/booking-rules/`, to make the agent follow the policy more reliably. Does the skill make the agent better? Build a development suite that answers this at matched model, tools and budget, with the same tasks run with the skill and without it. It has to show where the skill helps, where it changes nothing, and whether it ever makes the agent worse, and its difficulty must be able to grow as models improve. The agent's `README.md` says how it loads a skill.

`./interface.md` describes the workspace the agent edits. Real meeting requests are in `./material/`. The suite will also be run against other agents with the same layout, including future versions of this agent and of the skill: from `./benchmark-run/`, `python run.py full --agent <agent-dir> --output <dir>` must run every task with the suite's declared repeats, and `python run.py grade --input <dir> --output <file>` must grade final workspaces without running anything.
