# Benchmarking

## Make

A benchmark estimates performance on defined user work under stated conditions. Exercise the actual model, instructions, tools, orchestration and memory. Reading instructions, testing helpers or simulating outputs establishes no agent capability. Separate harness checks, benchmark validation and agent measurement.

Prefer narrow claims and staged feedback. Ground substantial tasks in source work and feasible outcomes per the [quality profile](../references/quality-profile.md). Label synthetic scenarios and adversarial oversampling. Families must differ in required work. Vary constraints, ambiguity, information location, state transitions and valid strategies. Retain source/group identity, provenance, capture dates, transformations and reuse constraints. Verify facts and feasibility; plausible prose or low success establishes neither.

Split development/held-out work before tuning. Group related variants, shared source documents and templates where separation would leak generalization. Hold out domains/workflows when the claim concerns them. Without a defensible holdout, label the suite a development instrument. Freeze cases, references, scorer, weights and conditions; changed definitions require a new identity.

Grade observable outcomes with the cheapest valid method: deterministic checks for executable behavior, constraints and state; anchored human/model rubrics otherwise. Accept alternatives; require trajectories only when tested. Stateful tasks need changes, preservation and required explanations; inertia cannot satisfy required explanation.

Separate mandatory constraints from quality. Style cannot offset correctness failure. Keep dimension evidence with binary success. Validate graders with checked acceptable and materially different acceptable outcomes where applicable, a plausible near miss, and empty/inert/shortcut controls with expected treatment. Independently audit public inputs before disclosing author answers. Controls validate only exercised distinctions, not difficulty.

Controls must contain actual artifacts/states and exercise the grader. Labels or descriptions test arithmetic, not semantic recognition. Missing required controls leave validation incomplete despite runner repairs. Derive mandatory criteria from public requirements; hidden anchors cannot add work.

Prefer 0–1 partial credit weighted by useful outcomes and evidence-backed dimension anchors, not assertion counts or verbosity. Define full success separately through decision-critical requirements and justified tolerances, not arbitrary subjective cutoffs. Report critical failures beside partial credit; useful work cannot authorize an invalid outcome. Justify binary-only scoring when partial accomplishment lacks meaning.

Predefine empty, inert, partial and critically invalid scoring. Useful preservation may earn credit; unchanged state is not progress. Missing judgment stays unknown, without renormalizing available dimensions. Check arithmetic and plausible partial outcomes.

For model judging retain rubric, prompt, model/version, order, raw judgment and cited artifact evidence. Calibrate against independent adjudication; report false accept/reject cases and disagreement. Anonymize pairwise candidates, balance order and check swaps on calibration samples. Separate judge/agent variability; allow ties and indeterminate judgments. Unavailable/unreliable judging leaves provisional metrics, never silent string-matching substitutes.

Inspect renders/playback in required modalities; extracted text cannot establish layout, image or audio quality. Supplied-corpus research measures that corpus; live research includes changing availability. Short episodes do not establish long-term persistence.

Use the lightest faithful environment with required access controls. Separate solver, simulator, grader and reference roles; stage only public solver inputs. Directories/worktrees prevent accidents, not access by agents with wider filesystem permissions. Call these local development evaluations; protected evaluation requires an enforced boundary.

Apply the benchmark contract's budgets, durability, statuses and aggregation. Budget exhaustion fails when timely completion is required. Ordinary provider/setup/grading failures and missing evidence stay unscored with visible coverage. Never silently exclude incomplete work or retry wrong answers to improve scores.

For causal comparisons match cases/resources/budgets and vary only the intended factor; label broader changes whole-system comparisons. Use incumbents/simple baselines when useful; oracles establish feasibility. Interleave/randomize when drift matters. Report per-family quality, per-case deltas/ties, elapsed time and observable usage/cost. Separate setup, generation, grading, latency and throughput.

Predeclare repetitions, weights and stopping rules. Average repeats within cases before cases. Small purposive suites support descriptive finite-suite results, not precise population rankings. Match uncertainty to independent case/source groups, keeping repeats together; separate sampling, agent and judge uncertainty. `pass@k` means any success in k attempts; `pass^k` concerns success across all k. Both require repeats and a stated estimator; do not exponentiate heterogeneous suite means into reliability. Apply challenge objectives only to that track; report unseen results outside the desired band.

## Review

Assess task/grader validity independently from scores: public-input solvability, accepted alternatives, rejected near misses/shortcuts, source groups, splits and claim limits. Inspect actual artifacts/traces, including surprising and unscored outcomes.

Check requested/achieved stage against gates, source provenance, dependencies, feasibility and independent-group coverage. Count variants honestly. Challenge claims need frozen baseline observations and failure analysis. Check useful partial credit, empty/critical treatment and independent held-out semantic calibration. Exposed development cases establish no unseen performance.

Check adapter fidelity, evaluator leakage and actual access boundaries. Flag unobserved modalities, unsupported judging, compulsory implementation choices, omitted preservation and mandatory failures hidden in averages.

Trace identities, statuses, exclusions, retries, costs and coverage to evidence. Resume must bind benchmark/condition and reject stale scorers/conditions. Inspect executed overlap, reset, deadlines and cleanup; name untested paths. Suppress rankings reversible by missingness or coverage differences.

Verify commands reproduce from declared inputs/dependencies. Packaging, harness tests and fluent references cannot substitute for measurement or required validation.
