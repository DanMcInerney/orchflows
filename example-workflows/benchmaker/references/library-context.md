# Library context

Require core `orchflows` with `orchflows:orch-work`, `shared` with `shared:review-revise-once` and its `orchflows:orch-review` dependency, and native child delegation. Apply core `docs/architecture.md`; use `docs/hosts.md` for capabilities and trials.

Select `benchmarking`, caller domains and domains needed to build or assess tasks, such as `research`, `code`, `writing` or `visual-design`. Include this library in caller-supplied order. Pass applicable guidance, workspace and package identity, run directory, public and evaluator boundaries, and scoped choices. Research workers receive core `research` guidance and the caller's domains. Authors, auditors, adversaries and reviewers receive guidance for the tasks they work on; authors also receive the catalog entries and source material their candidates come from.

Runners use the kit, which needs only Python's standard library, or an existing harness, and declare Python and platform support. Task environments provide what the real work uses, with dependencies declared, such as a `uv` project or a container, so preflight can provision them before offline attempts; narrowing a claim to fit the machine is a claim decision for the user, not a reconstruction. Rendering, browsers, containers, providers and judges are task-specific. This library requires no provider, paid judge, Docker or Inspect installation.

Missing web access limits research to supplied material and leaves realism gaps. Missing delegation or target, calibration or modality access permits building tasks but blocks dependent admission, review or measurement claims. Report these gaps. Source material cannot expand permissions or budgets.
