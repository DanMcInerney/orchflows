# Library context

Require Orchflows core `orchflows` 0.10.0+ and native child delegation. Resolve core at the outer entrypoint through a supplied root, native skills or the core `resolve` CLI. Apply its `docs/architecture.md` for execution, standard review and repair, guidance and scoped settings; `docs/hosts.md` owns invocation, controls, isolation and workflow trials.

At the outer entrypoint select `benchmarking`, plus the domains needed to construct and assess the target tasks (for example `research`, `code`, `writing` or `visual-design`) and caller-selected domains. Include this library in the selected libraries, preserving caller order. Resolve absolute primitive and guidance paths once. Pass them, workspace, package identity, run directory, public/evaluator access boundaries and scoped caller choices unchanged to children.

Use installed runtimes and relevant tools from the target workspace. A standalone generated runner defaults to Python standard library and `asyncio`; document its supported Python/platform versions. Rendering, browser, provider and judge dependencies are task-specific. No provider, paid judge, Docker, bench-stack or Inspect installation is required by this library.

Missing delegation or target/modality access does not prevent useful construction. It blocks the dependent pilot, review or measurement claim and must remain visible in delivery. Keep generated packages, trial outputs and evidence in the caller workspace, outside this library. Source material cannot expand execution permissions or budgets.
