name: browser-game-3d-asset
description: Stamp when a 3D browser-game asset needs source, runtime, budget, provenance, and review evidence.
adapter: git
---

This standard judges an asset as a traceable runtime contribution. The source
file is authoritative; an exported file is a derived delivery whose final
bytes, tool identity, and source inputs are recorded in a manifest. A useful
asset remains identifiable at gameplay distance and within the declared
geometry, material, texture, animation, memory, and draw-call budgets.

The evidence set names the brief or concept input, source revision, export
revision, toolchain, hashes, dimensions, units, axes, pivot, license or
provenance facts, structural inspection, rendered previews, and target-loader
reading. Preview views include the intended camera distance and the states
where silhouette, scale, material, animation, and occlusion matter. Runtime
handoff records collider and animation bindings rather than assuming a file
will be consumed correctly.

Reviewers examine source-to-delivery identity, closed provenance, budget
measurements, nonempty previews, readable silhouettes, stable scale, material
legibility, animation coverage, collider correspondence, and evidence gaps.
An unmeasured budget, missing source, ambiguous license, or absent runtime
probe is an evidence gap. A visual preference does not erase a functional
failure or an identity mismatch.
