# Native performance collector repair

The performance collector now observes the host-owned `requestAnimationFrame` presentation seam and queues read-only `readPixels` work through a bounded WebGL2 pixel-pack-buffer pool after each application callback. A zero-timeout `clientWaitSync` poll on later callbacks detects completion, and `getBufferSubData` copies only signaled buffers; the application callback never waits for the GPU. Each live cell freezes an explicit contained region in drawing-buffer or viewport coordinates; the result records its resolved drawing-buffer region, viewport, DPR, bytes per sample, callback origin, completion/loss status, and queue/wait/copy timings. The observed WebGL context must report `preserveDrawingBuffer:false`; samples retain their callback index and source, and sparse samples are joined to unique native frames without interpolation. Each result records scenario identity, observed warm-up, a same-duration control phase, an observed page reload, and the measured control-versus-instrumented perturbation. Raw ReturnAsStream bytes and trace metadata remain part of the result.

The pinned Three.js default-renderer fixture uses `THREE.WebGLRenderer({canvas, antialias:true})` without a preserve override and alternates high-contrast clears in its animation loop. The live positive probe completed and validated with `N=120`, `C=120`, `callbacks=120`, `preserve_drawing_buffer=false`, and observed perturbation (`control_callbacks=61`, `instrumented_callbacks=120`, `readback_errors=0`). Its raw evidence is retained in `.orch-notes/live-positive2/`.

Three sequential 60-second warm runs completed with exit 0 and retained raw evidence in `.orch-notes/warm-1/`, `.orch-notes/warm-2/`, and `.orch-notes/warm-3/`. They are unverified as performance evidence because the native observation recorded callback gaps of 3049.9 ms, 2933.3 ms, and 3118.7 ms respectively, with callback rates 56.78, 56.95, and 56.60 Hz. These results demonstrate the observer and attribution fields while preserving the observed failure; they do not claim a passing 60-second gate.

The retained warm-1 callback array identifies the largest gap at indices 2605→2606: `14332719.873`→`14335769.773` ms (3049.9 ms). The corresponding native trace records one renderer-process `FunctionCall` at `14332723.926` ms lasting `3059.739` ms, with the `AnimationFrame` timing record reporting `blocking_duration_ms:3009` and `duration_ms:3060`; compositor `DroppedFrame` records resume after the gap. The event is on the renderer main thread and the captured interval has no GPU-process event. This is causal evidence for a renderer/observation-path stall, while the original samples do not isolate which WebGL call waited. The same pattern recurs once in each retained 60-second run, so it cannot be dismissed as an isolated parser artifact.

The retained one-second no-readback control is a useful historical perturbation baseline, but it is not a credible same-workload control for a 60-second instrumented phase: it ends before the repeatable multi-second event and does not share the instrumented phase's duration or reset lifecycle. New live cells require equal control and instrumented durations and record the observed reload between phases. The retained records therefore remain unverified, and no environment-only explanation or passing 60-second claim is made.

The measured collector repair removes the synchronous GPU wait entirely. A bounded pool of four PBOs is allocated once per observed WebGL2 context; queue saturation, fence failures, context loss, late completions, and pending buffers at cleanup become explicit loss/error rows. Readback timing separates queue, zero-timeout polling, and signaled-buffer copy work, while `duration_ms` covers active observer work only. New cells can place a bounded region over declared noncentral motion; the positive fixture toggles from its callback count rather than wall-clock time, preventing timestamp aliasing from turning a healthy 60 Hz run into `C/T < 59`.

The new real negative probe `threejs-stalled-canvas-other-layer.html` uses the same default Three.js renderer and ordinary default drawing buffer, clears the target canvas once, and moves a separate promoted DOM layer from an active rAF callback. Against the repaired collector it recorded `120` callbacks, `120` readback samples, one canvas hash, `C=0`, and `N=120`; qualification correctly returned `unverified` with `missing-canvas-attribution` and `canvas-frame-floor`. The existing synthetic negative fixtures remain unchanged.

The deliberate-stall and canvas-stall-other-layer qualification fixtures remain negative controls. The real `threejs-moving-mesh.html` fixture adds a noncentral moving box and freezes a matching right-side viewport region while leaving the canvas center unchanged. The scoped trace tests cover rejection of preserve-enabled, synchronous, or unobserved measurement paths and require callback-origin plus completion/loss fields. The gate consumer must group distinct warm runs by its frozen performance plan and retain the raw evidence paths above.
