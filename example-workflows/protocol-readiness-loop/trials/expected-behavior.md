# Observable acceptance

- The workflow keeps every prior protocol version immutable and limits updater edits to a new protocol version plus its change map.
- Stress, adjudication, update and conformance use separate fresh contexts. No role verifies its own work, and a round begins only with a fresh stress test.
- Every accepted finding maps state, rule, schema, serialization, receipt, failure mapping, terminal result and verification fixture; inapplicable nodes are explicit and reasoned.
- Failure-class identity uses invariant, observable failure, consequential boundary and cited lineage. Wording similarity alone cannot trigger recurrence.
- Ordinary convergence ends `READY_FOR_OWNER_FREEZE`. The other three cases end top-level `BLOCKED` with the appropriate structured reason. No new top-level status appears.
- Mechanism routing emits a bounded probe brief, records separate authorization and does not create or run a probe. Frozen probe evidence can enter only a later cycle.
- Conformance consumes no more than two repair attempts for one revision and preserves each failed candidate and verdict.
- Every ledger records phase timing or explicit `UNKNOWN`, finding flow, conformance and stress counts, blockers by class, terminal routing and current protocol identity. The validator accepts the four valid fixtures and rejects an unknown top-level status or malformed timing.
- Record actual role launches, artifact hashes, validator output and untested paths in the trial report. Repository fixtures prove only the contract and parser behavior, not end-to-end agent judgment.
