# 5. Routing, improvement evidence, and integrated proof

## Goal

The root announces the smallest useful lane before it acts, uses detailed shape text only for a team frame, and can de-escalate when investigation removes uncertainty. Improvement documentation describes what current records and cluster output actually establish. One integrated run proves the revised standards, workspace, package, profile, routing, and durability seams together.

## Owners and changes

Remove `tickets_mint._one_lane` and its numbered-subquestion heuristic. Punctuation and list shape do not establish independent lanes. Explicit fan-out, ownership, isolation, and dependency needs still justify a team frame through their existing owners.

The host block distinguishes routing announcements from team shape records. Direct and worker routes say their lane before work in a short sentence. Team work records the detailed shape passed to `frame-open`. A route may move down after an investigation shows the work is smaller, or move up when an actual second concern or split appears. Explicit workflows and user cost choices win. Expensive named campaigns such as evolve, benchmaker, or skill-tournament remain named-only and never start as an invisible routing side effect.

The routing text should be evaluated as prompting guidance. Durability, isolation, and ownership checks remain enforced mechanics. Guidance that evaluation later shows unnecessary may be removed through an ordinary reviewed change; this series adds no automatic deletion framework.

`rules/improvement.md`, friction reporting, and self-improve documentation keep the current bounded raw records and existing readers. Deterministic lexical clusters are navigation aids for a reviewer. They do not prove two records have the same cause or meet a semantic recurrence bar. Agent judgment remains responsible for selecting a causal owner and deciding whether evidence warrants a proposal. Clarify shared normalization or display helpers and test them where inconsistent, but do not widen intake, change thresholds, add embeddings, invent a signals schema, or claim machine clustering now performs semantic mining.

Accepted proposals still use ordinary scoped `do`, `judge`, and `land` work. This stage does not change self-improve, evolve, or game example workflows. It does not activate a winner or convert a one-off observation into a global rule.

## Exclusions

Do not keep the numbered-list lane guess under another name, require team shape syntax for direct work, forbid de-escalation, or silently invoke costly campaigns. Do not build semantic claims from aggregate singleton counts, introduce a new improvement funnel, or add new host implementations. Workflow notation and `example-workflows/` remain deferred.

## Observable proof

Routing tests cover a small direct change, one isolated worker assignment, a team frame with an explicit shape, de-escalation after investigation, escalation after a real second concern, an explicitly named workflow, and a costly campaign that stays dormant until named. A numbered but single-owner goal no longer refuses merely because it contains several numbered items.

Improvement tests feed paraphrases and look-alike text through the existing deterministic clusterer and assert only stable grouping output, never semantic equivalence. A reviewer can reach the raw bounded records, record a causal-owner judgment, and route a resulting change through the existing ticket path. Documentation labels any aggregate measurements as observations with source and date rather than universal performance facts.

The integrated dogfood uses `checkpointed-build` or the equivalent existing frame plus `do`, `judge`, and `land`; it does not add `implement-spec`. From a stable checkout, a source-backed fixture creates a temporary public package with a private helper and local standard, composes it with an orthogonal public standard, derives one workspace from the target, runs a sequential worker assignment, and drives the landed mixed identities through the planner-profile judge boundary. Exercise one literal-check failure and one corrected package probe. Record source identity, canonical pins, host/profile binding, workspace selection, artifact and findings lines, and the outside probe; add live fresh-judge evidence only when a host is available.

The integrated proof also records a route that de-escalates and one friction item whose lexical cluster is treated only as navigation. Acceptance requires focused routing and improvement-reader tests, source-backed integration tests, the outside probe, and the repository required checks once at the coherent final tip. Live-host evidence is included only for available hosts. Installation, if needed for a consumer phase, waits until all active consumers of the prior runtime finish and uses the stable accepted checkout.
