# 5. Authoring, routing, and improvement

Status: proposed. Implement after stage 4's standards and mixed-review evidence are accepted.

## Dependencies

Stage 4's compact standards and mixed-artifact judge; the existing host block, rings/bundles/pins/trust, orchflows new/list/check/sync, rules/improvement.md, rules/loops.md, and the shipped self-improve, evolve, skill-tournament, and benchmaker workflows. Discover the installed library before the dogfood: baseline examples include super-research, checkpointed-build, orch-do, and orch-judge, but conceptual labels such as engine-research, build-game, review, and browser-game-qa are not assumed to be installed names. Cross-host proof uses only host records and CLIs actually detected on the machine.

## Goal

An agent receiving an ordinary request is autorouted to the smallest useful existing operation, while a specific or recurring sequence can be named and shared as a workflow. Friction and worklogs reach their causal owner through self-improve, and evolve can compare any frozen executable or non-runnable artifact without silently activating a winner. The complete game-building reference workflow runs through the accepted library on every available host surface.

## Current-code evidence

The custom authoring document already defines project/home/import/lib placement, trust, bundle pins, dependency declarations, and the orchflows new/check/sync flows. The host block and rules/composition.md already route smallest-first, preserve exact call grammar, and distinguish ordinary prose from a reusable workflow. tickets_mint._one_lane currently hardcodes a numbered-subquestion heuristic for the evidence-store adapter, which can refuse a legitimate compact brief before a workflow can choose its shape. rules/improvement.md already defines friction recurrence, causal owners, replay, human-reviewed activation, and the shipped self-improve workflow. rules/loops.md already defines frozen goals, external done checks, fresh-context rounds, unsuccessful exits, and winner-independent bounds. The existing evolve workflow and references are the substrate; the gap is to make their applicability and routing explicit without adding a parallel campaign engine.

## Bounded changes and causal owners

1. Update authoring guidance and its validator for the package shape accepted in stage 2, including private scripts/references/local standards, scope placement, dependency declarations, and generated inert host adapters. Keep public API prose concise and machine fields only where a script or resolver consumes them.
2. Remove the evidence-store-specific _one_lane numbered-subquestion refusal from tickets_mint.py. Routing should report the need for a frame when a caller asks for fan-out, but a compact free-form brief is not itself a proof of multiple lanes. Preserve explicit frame/fan-out guidance and deterministic bounds.
3. Specify economical autorouting in the host block: reuse a current primitive for common blog/research/code work; open a named workflow only when sequencing, recurrence, crash recovery, independence, or audit value earns it; let a root improvise the same primitives; de-escalate when uncertainty is resolved. An explicit named workflow or cost choice wins. A trivial task does not acquire mandatory outline/decompose/review, and an expensive evolve campaign requires explicit invocation.
4. Make self-improve's capture and mining path cover friction logs, worklogs, feedback, and machine events plus agent explanatory notes. The harvester remains mechanical; the proposal names one causal owner (environment, custom workflow, project, or library). A recurring cluster or checked contradiction qualifies; one-off noise stays evidence. Accepted changes are delivered by ordinary do/judge/land and replay the producing item.
5. Generalize evolve's frozen evaluation contract to executable code, prose, designs, standards, and workflows. Candidate versions are fixed before comparison; criteria are distinct from private evaluation examples; blind comparison and held-out evidence are used where useful; unsuccessful exits are recorded; a score is never fabricated for schema completeness. Winner selection and activation remain separate, with existing human-reviewed activation policy preserved.
6. Add a final host proof using Claude, Codex, and Grok records that are detected and available. The adapter tests launch-field legality, profile resolution, inert installed files, ring visibility, and typed result forwarding. A future Pi or Antigravity adapter is an optional separately executable extension, not a prerequisite for the core.

## Exclusions

Do not add a global workflow registry, a mandatory scheduler/daemon, one agent per question, a new persona/type system, an automatic expensive campaign, or a host-specific syntax in generic workflow prose. Do not turn improvement logs into executable instructions, make a local project defect a global rule without evidence, or activate an evolve winner automatically. Do not claim an external game's or Worldclaw's implementation.

## Practical dogfood exercise

Ask a fresh agent: “build me a workflow that builds games.” It first runs the installed-library discovery and records the exact callable names, rings, and source paths. It may reuse suitable installed components such as super-research, checkpointed-build, orch-do, and orch-judge. If an engine-research or browser-game-qa component is absent, the agent authors the missing wrappers and private resources locally as part of creating the requested project workflow with `orchflows new workflow build-game`; the conceptual labels remain prose until a concrete callable name and source identity exist. A stage 2 fixture is reusable only when its preserved source identity and absolute path are supplied explicitly; otherwise this stage creates the disposable fixture and records its source. Stage 5 owns and preserves the resulting reference workflow/component sources and the recorded run. Run `orchflows check` and exercise the authored workflow only after validation. The workflow runs this reference shape: intent → scene plan → global assets/terrain → render/judge/refine → region planning → independent region generation/placement/refinement → integrate → global/local QA. Engine research fans out and gathers comparison evidence into build-game; browser-game QA owns its private checks and narrowing. Use placeholder or existing assets when no image service is available. Run one executable game candidate and one judged workflow/standard candidate through evolve with frozen criteria and blind comparison. Feed any friction to self-improve, observe the selected causal owner, and require a human-reviewed activation step before changing the live workflow.

## Acceptance evidence

Record the installed-library discovery output with exact callable names, rings, source paths, and the selected reuse/authorship decisions. Record routing decisions for trivial, common, named, and recurring requests, including a case where the route de-escalates. Record self-improve harvest/replay evidence, an environment probe, a workflow-owner proposal, and an unsuccessful evolve exit. Record at least one blind comparison and one held-out result for a non-runnable artifact, and prove the winner is not active until explicitly accepted. Run the game dogfood, preserving the authored workflow/component source and run identity, the available-host adapter matrix, affected checks, the root's full required row, and git diff --check; relay artifact: and findings: lines exactly.

## Migration, compatibility, and recovery

Existing autorouting, named workflows, friction logs, evolve records, and activation policy remain compatible. New routing guidance cannot reinterpret a sealed ticket or change an installed live run. Existing campaigns keep their frozen evaluation identities; a new artifact kind opts into the generalized evolve contract. The authored game workflow and any missing component wrappers are retained with their source identities and paths so later runs do not depend on deleted scratch inputs. If a host or workflow proof fails, report a gap for that host, leave the accepted predecessor installed, and recover from the durable frame/worklog. A future adapter is added only in a separately accepted source identity with its own probes and rollback.
