# Native observer diagnosis: the tracing category set is the next repair seam

Checked 2026-09-06. The remaining repeatable three-second pause does not require WebGL readback: the same pause occurs with readback disabled and native tracing enabled. The strongest repair candidate is therefore the trace category set, specifically the broad `cc` and `disabled-by-default-cc.debug` categories. Their overhead is measured, but it is not yet proven to cause the pause. One matched trace-only A/B test can decide that question without weakening frame or canvas attribution.

The trace-only evidence is from artifact `2286637bcef84ed33aded21c1fec6a5807b9a0ea`, headed Chrome 152.0.7977.76, Playwright Core, WebGL2 through Intel ANGLE D3D11, seed 1, and the fixed 640×360/DPR 1 moving-mesh cell. The newest combined evidence uses clean B1.28 checkpoint `627e7dd8cf5126b0df9d09c6ac141e3732dfcf63`, which is unlanded at the time of this diagnosis. Root preserved the B1.28 configurations, summaries, and raw traces under `.orch-notes/native-isolation-20260906` before candidate retirement.

## Why the category reduction preserves the contract

The pinned DevTools [`FramesHandler`](https://github.com/ChromeDevTools/devtools-frontend/blob/9f9f40ba5bca7e385be30535cdbf01a3a7e5ba44/front_end/models/trace/handlers/FramesHandler.ts) filters for the frame events listed above, `LayerTreeHostImpl` snapshots, top-level tasks, main-frame markers, and paint events; it depends on Meta, Renderer, and LayerTree handlers. The pinned [`LayerTreeHandler`](https://github.com/ChromeDevTools/devtools-frontend/blob/9f9f40ba5bca7e385be30535cdbf01a3a7e5ba44/front_end/models/trace/handlers/LayerTreeHandler.ts) consumes paint, display-list snapshot, update-layer, and set-layer-tree events. Neither handler declares broad `cc` debug activity as a semantic input.

Chrome DevTools itself starts a normal performance recording with `-*` followed by its curated defaults; those [pinned defaults](https://github.com/ChromeDevTools/devtools-frontend/blob/9f9f40ba5bca7e385be30535cdbf01a3a7e5ba44/front_end/models/trace/types/TraceEvents.ts#L3086-L3113) include `devtools.timeline` and `.timeline.frame`, omit broad `cc` and `disabled-by-default-cc.debug`, and add `.timeline.layers` only for advanced paint capture. This workflow must retain `.timeline.layers` because its canvas attribution reads those snapshots. Its smallest candidate list is therefore:

```text
devtools.timeline
disabled-by-default-devtools.timeline.frame
disabled-by-default-devtools.timeline.layers
```

Do not add `excludedCategories:["*"]` as a guessed fix. Chromium's [trace configuration implementation](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/base/trace_event/trace_config.cc#806) already disables `*` when an included-category list is nonempty. The CDP [Tracing contract](https://chromedevtools.github.io/devtools-protocol/tot/Tracing/) also says the default is `recordUntilFull`, the default buffer is 200 MiB, and `tracingComplete.dataLossOccurred` reports known loss. Those facts explain the configurations; they do not prove that buffer mode caused this pause.

## Minimal patch and decisive tests

1. In `trace_frames.mjs`, remove only `cc` and `disabled-by-default-cc.debug` from the default category list. Preserve `ReturnAsStream`, explicit record mode and buffer metadata, clocks, padding, raw persistence, loss checks, readback, callback floors, stall guard, and canvas attribution. Add a focused contract check that the three retained categories and required event kinds reach the parser; do not make a performance test assert prose or timing.
2. In a quiet, visible, focused session with no Blender/browser competitor, run a matched 60-second trace-only pair on the frozen moving-mesh cell. Hold commit, URL, seed, viewport/DPR, region, warm-up, record mode, 512 MiB buffer, browser/backend, and order accounting fixed; vary only full-five versus reduced-three categories. Retain raw hashes, event counts by category, PID/TID names, callback gaps, required-event inventory, layer snapshots, and loss status.
3. If full-five fails and reduced-three passes the callback thresholds with required frame/layer events intact, the category set is causal: keep the two-category deletion and run the identical combined cell. If both fail, reject the category hypothesis and next split `.timeline.layers` from `timeline + frame` in diagnostic-only runs; loss of canvas attribution is expected and cannot become an acceptance configuration. If both pass, reverse and repeat the pair because the reproducer or host state changed. If reduced trace-only passes but combined fails, tracing is repaired and the remaining readback/host path must be isolated separately.
4. Only after the reduced combined cell qualifies should the existing three warm 60-second cells and real static-other-layer and deliberate-stall negatives run. Do not reuse the already failed remedies: larger buffer alone, record mode alone, larger PBO queue, reduced workload/region, relaxed floors, ignored stalls, or removed attribution guards.

This plan deliberately makes no runtime change and claims no host limitation. The present evidence proves the observer boundary and the next discriminating test; it does not yet prove the category hypothesis.
