## Audience model

Every doc except the human whitelist is read by an agent with ZERO
session memory, mid-task, paying per token. Docs are lookup surfaces,
not tutorials. A doc succeeds when an amnesiac agent holding only
AGENTS.md + `docs/vocabulary.md` can act correctly after one read.

**Human whitelist** (narrative allowed, everything else is agent-facing):
`README.md`, `TICKETS.md`, `DESIGN.md`, `docs/library-review.md`,
`THIRD_PARTY_NOTICES.md`, `LICENSE`.

## Rules for agent-facing docs

1. First sentence states what the file owns and when to read it.
2. One fact, one owner; every other mention is a link. Never restate a
   default — state only deviations (visibility §3). The 62 validator
   near-duplicate WARNs are the backlog; do not add to it, reduce it
   where your edit touches an offender.
3. Imperative present tense. No history, no motivation, no "recently",
   no "now" — rationale lives in DESIGN.md, history in git and
   supersession records only.
4. Commands are exact and copy-pasteable: full interpreter prefix
   (`uv run --no-project python ...`), real paths from repo root, no
   ellipses, no placeholders except documented `<angle>` args.
5. Every named path, command, flag, field, and clause citation must
   exist at the tip. A citation like "topology §5a" is a defect unless
   the target carries that label.
6. Shapes and enums appear only via generated blocks or links to them —
   never hand-written tables.
7. New nouns get a `docs/vocabulary.md` entry before first use; terms
   mean exactly what vocabulary says (a different meaning needs a
   different word).
8. Word ceilings per `rules/token-economy.md` hold. When adding a
   sentence would breach a ceiling, delete a weaker sentence — do not
   compress into ambiguity.
9. No LLM-shaped seams: a doc may not instruct hand-authoring of
   anything a script owns (packets, worktrees, launch specs, receipts).
   After U1–U9, the scripts own more — docs must shed the corresponding
   manual instructions, not keep them as fallback lore.
10. Structure for grep: stable headings, one topic per section, kebab
    anchors; an agent finds a fact by heading scan, not full read.
