## Threads (ranked)

**T1 — The composition executor gap.** The supersession defined the
composition contract but no executor. Confirmed independently by the
research trace and the adversarial lane: orch-spec's Return emits a
composition-instance path nothing reads
(orch-spec/SKILL.md:23-24 is passive voice — "a successor spec is
written" — with no actor); orch-deliver requires exactly one spec
(orch-deliver/SKILL.md:7); no skill reads
`.orch/runs/<run>/composition.md`, so the promised cross-session
resumption (contracts/composition.md:37) and `done_check` invocation
(:23-25) have no implementation. Remedy: **add** — the one lawful
producer-gap add of this pass (constitution 4, 5, 7): one engine
skill that (a) validates any composition — named or instance —
against the admission sentence at load, (b) executes steps by edges:
seq re-enters `orch-spec` with the predecessor's result identity as
evidence (spec.md's only-editor law holds — the engine invokes, never
writes), par through the delegation boundary, loop through
`orch-loop`, (c) runs `done_check` in a fresh context receiving only
the final envelope and the spec — never internal verdicts, (d)
re-evaluates `done_check` on every scheduled trigger, (e) returns one
envelope. Closes research findings 1-5 and adversarial threads 3, 5,
7 in one move. Est. +40 lines (engine budget) + rewords in orch-spec
Return, host-block branch 3, topology §7 naming the engine.

## Meta-analysis

The threads connect at one cause: **the supersession shipped the
composition data model without its runtime**. T1 is the missing
runtime; T2 is its missing admission teeth; the adversarial lane's
worst gaming paths (unvalidated instances, laundered done_checks,
stale scheduled state) are all things a single executor engine
naturally enforces at load and at close. The single simplifying move
is the T1 engine — one ~40-line skill that closes eight findings
across three lanes and completes the two-entrypoint model it belongs
to.
