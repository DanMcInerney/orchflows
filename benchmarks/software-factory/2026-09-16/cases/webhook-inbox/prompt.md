Implement these HTTP contracts:

* `GET /health` is unauthenticated and returns HTTP 200 with the JSON object `{"status":"ok"}`. It must disclose no credentials or stored events.
* `POST /webhooks/{tenant}` accepts a UTF-8 JSON object whose raw body is at most 65,536 bytes, inclusive. Use SQLite to persist the exact raw body and exact event ID. Require `X-Event-ID`, `X-Timestamp`, and `X-Signature` headers. The event ID is 1–128 visible ASCII characters, with no leading or trailing whitespace; SQL-looking strings are valid data. The timestamp is a canonical nonnegative decimal Unix-seconds integer (no sign, spaces, or leading zeros except `0`). Accept an absolute difference of at most 300 seconds from the server's current Unix time; reject stale or future timestamps outside that window with 401. The signature is exactly 64 lowercase hexadecimal characters representing HMAC-SHA256 with the tenant's UTF-8 secret over `timestamp + '.' + raw_body`, where the timestamp bytes are the header's ASCII bytes. Use constant-time comparison for authentication credentials/signatures. A syntactically valid but incorrect signature is 401.
* Scope idempotency by `(tenant, event ID)`. First accepted submission returns HTTP 201 and a JSON object containing `event_id` and `duplicate:false`. An authenticated retry with byte-identical body returns HTTP 200 with `event_id` and `duplicate:true`. A validly authenticated submission with that ID but any different raw bytes returns 409, even if both bodies parse to the same JSON value. Recheck authentication and timestamp on every submission, including duplicates. A failed request must not reserve an ID, insert an event, change an existing body, or create another partial effect. Concurrent submissions must preserve these rules and leave exactly one stored event per tenant/ID.
* `GET /events/{tenant}` requires `Authorization: Bearer TOKEN` using that tenant's configured read token. Missing, malformed, or incorrect authorization is 401. Return HTTP 200 and a JSON object `{"items":[...],"next_cursor":...}`. Each item includes `sequence` (a positive integer), `event_id` (the exact ID), and `payload` (the parsed JSON object). Each tenant has stable, strictly increasing insertion sequences; gaps are allowed. List oldest insertions first by sequence, never by event ID, timestamp, or body. Retries/conflicts do not alter a stored sequence. Support optional `limit` (canonical decimal integer 1–100, default 50) and `cursor` (canonical nonnegative decimal string, default `0`). Return only events with sequence greater than the cursor. If more matching events exist after this page, `next_cursor` is the canonical decimal string of the last returned sequence; otherwise it is JSON null. Reusing the same cursor without writes returns the same page. A cursor beyond the last sequence yields an empty page and null. Numeric cursors have no tenant identity: using a number obtained from another tenant simply filters the authenticated tenant's own sequence and never reveals another tenant's rows. Reject unknown or repeated query parameters and malformed values with 400.

An unknown tenant returns 404. Otherwise, a malformed body (including a JSON array/scalar or invalid UTF-8), malformed required POST header, or malformed query is 400; an oversized body is 413. Missing POST authentication headers are malformed headers (400); syntactically malformed signatures are also 400. Unrecognized paths return 404. Successful and error responses use JSON objects. Require a valid Content-Length for POST bodies; reject a missing, negative, nondecimal, or otherwise malformed Content-Length with 400. Requests with multiple simultaneous faults may return any one applicable error; no particular validation order is required. Error responses must have no write effects.

The server must handle simultaneous requests, survive stop/restart with all accepted events and idempotency intact, and keep tenant authorization, writes, and reads isolated. A signature from one tenant must not authorize another tenant. Protect SQL operations from input interpreted as SQL. Do not rely on process memory for durability.
