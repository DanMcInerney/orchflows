### A — The T0 shape guard measures its own tombstones, so contract history can never be pruned

**Owner:** `tools/validate_support/lint.py` `_t0_shape` (:99–107).
**Remedy: reword** the guard (≈ +2 lines), which unlocks **delete** of

`validate_pin_supersessions` requires a supersession record only when a
contract's *named-field-and-enum surface* changes
(`lint.py:173`: `if _t0_shape(before) == _t0_shape(...): continue`).

record` paragraphs at the bottom. Retired names live in those paragraphs,
so the guard counts them as part of the current shape.

repository's own `_t0_shape`:

| `worklog.md` | 4 | 17 | `status` |
| `verdict.md` | 3 | 10 | — |
| **total** | **72** | **457** | |

`loop_stub` has **zero** references in any `.py` file
(`contracts/work-item.md:336,432` are both inside records; the loop engine
retired). It is kept inside the pinned shape by nothing but its own
obituary. Deleting the obituary therefore reads as a breaking shape change
and demands a *new* obituary. That is a ratchet, and it is the whole
arithmetic of the +1,313 header delta.

The loop has already turned once and the repository noticed:
`contracts/worklog.md:79` is a supersession record whose own text says
*"No named field or enum actually changed; the prior wording's incidental
`` `status` `` line-start happened to match the same heuristic that flags a

`tests/test_ticket_protocol.py:85` reads
`dispatch.partition("T0 supersession record")[0]` precisely so it grades
"the normative prose alone", with the comment *"a supersession record's
whole job is to name what it retired, so it names these on purpose."*
`_t0_shape` should partition the same way. Then the 72 records become
ordinary prose, deletable in one change with a clean `--pin`.

## Meta-analysis

Six of the seven threads are one cause wearing different clothes:
**this library grades its live surface and its history with the same
instrument, so history is never allowed to leave.**

Thread A is the mechanism in its purest form — `_t0_shape` cannot tell a
current enum from a retired one, so 29% of the contract tier is
unprunable, and the guard has already been observed manufacturing a
tombstone from a false positive. Thread B is the same failure at admission
time: the rule "a cell earns its slot only when machinery branches on it"
is prose, so `stages`, `assembly`, `identity_form` and `conflict_semantics`
were admitted and then never re-tested, and the tests that "cover" them
assert constants against copies of themselves. Thread C is what survives
when nothing asks "who calls this" — nine dead functions, 3,013 lines of
mutually-sustaining harness and tests, a linter nobody runs, a scope
parameter that is always the same value. Thread D is an exception dated
2026-08-28 that now outweighs its subject 45:1. Thread G is the drift you
get when the human surface and the machine are checked by different
oracles, or by none.

Thread E is the one different cause, and it is the sharpest finding here:
a shipped workflow that refuses on its first dispatch for every user who
is not standing in this repository. It is different because it is not
accretion — it is a boundary the checks do not look at.

**The single move that closes the most threads:** make "has a live
consumer" a mechanical question instead of a prose rule, and run it in
`tools/validate.py`. Concretely, one new validator pass that partitions
every contract at its first `T0 supersession record` before computing the
pinned shape (A), greps each declared pack cell, adapter field, vocabulary
entry and `--skill`/`--pack`/`--sheet` argument for a consumer outside its
own declaration (B, E, F3), and widens `LINKED_MD_ROOTS` to every shipped
tree (F2). That pass is perhaps 120 lines. It converts Threads A, B, E and
F from judgment into arithmetic, makes the 457 tombstone lines and the
3,013 harness lines deletable in one change each, and — the point — it
keeps them deletable next time, which is the property this library has
been missing since the 2026-08-26 pass measured 1,581 law lines against
today's 2,894.
